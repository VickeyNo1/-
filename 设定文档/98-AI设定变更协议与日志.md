# 98-AI设定变更协议与日志

本文件规定创作过程中发生整体设定变更时，用户与 AI 应如何修改文档、草稿和已发布事实。目标是让每次变更都可追踪、可检查、可回滚思路，不依赖 AI 凭印象在多份文件中自行猜测。

## 一、唯一权威来源

同一事实只能有一个主定义位置，其他文档只保留执行摘要和链接。

| 设定类型 | 权威文档 |
|---|---|
| 项目定位与当前阶段 | `00-项目总览.md` |
| 世界起源、底层规则、拉入、副本、管理员权限 | `01-世界观圣经.md` |
| 管理员背景、人格、立场、记忆考验、神降 | `02-管理员档案.md` |
| 领域、技能、等级、赋能、代行者质变 | `02-领域与能力体系.md` |
| 全书角色底色与长期弧 | `03-角色档案.md` |
| 官方、公司、地方势力与现实战力 | `04-现实势力.md` |
| 事故真相、全书阴谋与终局方向 | `05-阴谋与事故线.md` |
| 管理员关系、领域克制和强度排名 | `06-管理员关系与领域克制排名.md` |
| 正在执行的C级重构控制表 | `97-C级重构事务-20260815.md`（仅管理迁移状态，不替代专题权威定义） |
| 第一卷动态执行状态 | `../第一卷/` 对应专题文档 |
| 已确认、待定和废弃方向索引 | `99-待定问题与决策记录.md` |

根目录 `../小说项目交接文档.md` 是历史交接档，不参与设定优先级，也不随每次改动重复更新。

## 二、变更分级

### A级：局部修订

只影响一个角色细节、一个技能数值、一个章节道具或一句伏笔，不改变其他模块的因果。更新权威文档、连续性台账和受影响章节即可。

### B级：跨文档变更

影响两个以上模块，例如改变能力规则、人物势力、管理员立场、第一卷终点或副本通关机制。必须先制作影响分析表，经用户确认后统一修改。

### C级：整体设定变更

改变世界起源、底层规则、成长体系、总阴谋、核心人物身份或已经发布的关键事实。必须把它当作一次独立变更事务，不得边讨论边零散覆盖文档。

## 三、标准变更流程

### 第一步：用户提交变更卡

用户只需尽量说明以下五项；不知道的部分可以写“请 AI 分析”：

```text
变更目标：
旧设定：
新设定：
必须保留：
允许推翻：
当前正文状态：未写 / 草稿 / 定稿未发布 / 已发布至第X章
```

### 第二步：AI先分析，不立即改文档

AI必须输出一张影响表：

| 检查项 | 内容 |
|---|---|
| 直接权威文档 | 新设定首先应该改在哪里 |
| 全书连锁影响 | 管理员、能力、势力、阴谋和终局哪些部分会变化 |
| 第一卷影响 | 人物等级、案件、副本、伏笔和结尾是否需要改 |
| 正文影响 | 哪些草稿或已发布章节含有旧事实 |
| 冲突与漏洞 | 新设定会制造哪些时间线、能力或动机问题 |
| 推荐处理 | 保留、重写、降级为误导、改为角色误解或删除 |

只有用户确认影响分析和处理方向后，AI才能执行跨文档修改。

### 第三步：按顺序执行

1. 修改唯一权威文档中的主定义。
2. 修改 `99-待定问题与决策记录.md`，将旧方向移入废弃或被替代记录。
3. 同步第一卷总纲、人物轨迹、副本链和连续性台账。
4. 扫描所有草稿与正文中的旧关键词、同义词和因果结果。
5. 修复受影响章节，不只替换名词，还要重查人物动机、能力可行性和伏笔意义。
6. 在本文件的变更日志追加一条记录。
7. 执行一致性检查后，再提交 Git。

## 四、AI必须执行的影响扫描

整体变更不能只搜索旧名词。至少检查以下七类影响：

1. **定义影响**：规则、能力、等级和身份的直接描述。
2. **因果影响**：某人为什么进入副本、为什么获胜、为什么加入势力。
3. **人物影响**：目标、恐惧、底线、关系和成长弧是否仍成立。
4. **时间线影响**：事故、觉醒、入队、升级、神启和揭露顺序。
5. **知情度影响**：作者知道、角色知道和读者知道是否被混淆。
6. **伏笔影响**：旧伏笔是否失去回收对象，新设定是否缺少前置痕迹。
7. **已发布影响**：读者已经看到的事实能否解释，还是必须明确修订。

AI完成修改后，应报告：改了哪些权威定义、同步了哪些执行文档、哪些章节受影响、仍有哪些待定风险。

## 五、正文阶段的处理边界

### 尚未写正文

可以直接重构，但仍需保留变更日志，防止未来 AI 从旧讨论中恢复废弃设定。

### 已有草稿但未发布

允许重写草稿。必须同时更新连续性台账，旧草稿不得继续被当作上下文来源。

### 已定稿但未发布

先列出受影响章节，再决定整体重写还是局部修补。修改后重新做前后章连续性检查。

### 已经发布

不得静默把已发布事实当作从未存在。只能选择：

- 新设定与旧文本兼容，作为更深层真相揭露。
- 旧说法是角色误解、机构谎言或不完整证据，正文中必须给出合理依据。
- 通过后续事件改变规则，但要明确变化原因和时间点。
- 无法兼容时，记录为正式修订，并评估是否需要修改已发布章节或发布说明。

“这是伏笔”不能成为万能补丁。若旧文本没有留下误解空间，就应承认需要修订。

## 六、给 AI 的推荐指令

发生整体变更时，用户可以直接说：

```text
请按《98-AI设定变更协议与日志》处理一次B级/C级设定变更。
先读取相关权威文档、第一卷执行文档和连续性台账，只做影响分析，不修改文件。
旧设定是：……
新设定是：……
必须保留：……
当前正文已写/已发布到：……
等我确认影响分析后，再统一修改、检查并记录变更日志。
```

如果只是小修，可以说：

```text
这是一次A级局部修订。请确认唯一权威来源，修改后同步连续性台账，并检查当前单元和前后章节，不要扩散修改无关设定。
```

## 七、一致性检查清单

每次B级或C级变更结束前必须检查：

- 同一事实是否仍在两份文档中分别定义。
- 已确认、工作草案、待确认和废弃状态是否明确。
- 人物当前等级是否与有效副本次数一致。
- 已有技能是否满足阶段顺序，赋能层级是否越权。
- 管理员观察、神启和现实干预是否超过时期权限。
- 每个角色是否只知道当时有渠道得知的信息。
- 副本解法是否仍符合核心执念与真实因果。
- 第一卷揭露是否越过总纲的信息边界。
- 伏笔是否有首次出现、表层解释和预计回收。
- 草稿、定稿和已发布章节是否被区别处理。
- `git diff --check` 是否通过，中文编码和内部链接是否正常。
